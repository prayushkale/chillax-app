Two decisions are yours. The rest runs on its own.

Everything between the gates is the team's job. Nothing starts until you approve the sprint, and nothing ships until you approve the release. Try them.

  1. You describe what you wanta chat with the PM, or a plan you already wrote
  2. The PM plansepics, stories, acceptance criteria and a proposed sprint
  3. Sprint gateWaiting on you: 6 tickets proposed for SP-1
  4. Developers buildone git worktree and branch per ticket, your tests run
  5. The tech lead reviewsapproved diffs merge into dev, your checkout untouched
  6. QA testspromotes dev to qa, checks acceptance criteria, files bugs back
  7. Release gateWaiting on you: v0.1.0 passed QA
  8. Shippedqa merges to main, tagged, with release notes

What you get

Hire anyone
Pick the agent and the model per hire. Cheap models for simple tickets, strong ones for review.
An inbox for you
Permission requests, questions and both approvals wait in one place, so you only look when you're needed.
Watch it live
The same views in the terminal and the browser: board, team, chat, a live feed of every agent's tool calls, and token usage per ticket.
A bug loop
QA files bugs as tickets and they go back to a developer, like they would in a real team.
Pause, quit, resume
Every change is an event in a local log. Quit any time and the team, chats, tickets and inbox come back where you left them.
Ask for changes mid-sprint
New requests become tickets. If an agent gets stuck, it can escalate or hire help.

The full walkthrough

Five minutes, from a written plan to a tagged release: planning, hiring, both gates, the dev loop, the live view, QA and a finished project.

The honest trade-off

Chillax plans heavily, so it uses more tokens and more time than handing one prompt to one agent. In return, every piece of work has a ticket, the reasoning lives in its comments, and nothing reaches main without you.

Where it is now

Chillax is an MVP. Planning, hiring, both gates, the dev loop, QA and the bug loop work and are covered by end-to-end tests. Real agent runs have taken a project from the PM's plan to a tagged release. Next: Jira and GitHub tracker adapters, more agent backends, budgets and crash recovery.
